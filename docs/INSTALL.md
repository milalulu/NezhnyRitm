# Установка на iPhone через SideStore

## Подготовка SideStore (один раз)

Если SideStore уже установлен и обновляет свою подпись, переходите к следующему разделу.

1. Выполните [актуальную официальную подготовку](https://docs.sidestore.io/docs/installation/prerequisites) и [установку SideStore](https://docs.sidestore.io/docs/installation/install). Официальная инструкция использует iloader на компьютере и LocalDevVPN на iPhone; следуйте варианту для своей версии iOS.
2. На iOS 16+ включите «Настройки → Конфиденциальность и безопасность → Режим разработчика», перезагрузите устройство и подтвердите включение.
3. Если потребуется, подтвердите доверие профилю Apple Account в «Настройки → Основные → VPN и управление устройством».
4. Подключите предусмотренный инструкцией локальный VPN, войдите в SideStore с той же учётной записью, что использовалась при установке, откройте My Apps и обновите подпись самого SideStore.

## Установить «Мой нежный ритм»

1. Войдите в GitHub в Safari. Откройте [workflow сборки](https://github.com/milalulu/NezhnyRitm/actions/workflows/build-ipa.yml), выберите успешный запуск (зелёная отметка).
2. В Artifacts скачайте **NezhnyRitm-SideStore**. В «Файлах» откройте скачанный ZIP, чтобы распаковать его. Нужен файл **NezhnyRitm.ipa**, а не ZIP.
3. Включите локальный VPN, настроенный для SideStore. Откройте SideStore → My Apps → «+» и выберите `NezhnyRitm.ipa` в «Файлах». В версии с другим расположением кнопки используйте импорт IPA.
4. Дождитесь подписи и установки. SideStore подписывает приложение вашим сертификатом. Не пытайтесь устанавливать неподписанный IPA напрямую из «Файлов».
5. Запустите «Мой нежный ритм». Для базовой сборки доступ к «Здоровью» не требуется: шаги вводятся на вкладке «Шаги». Все остальные функции работают офлайн.
6. Разрешение на уведомления запрашивается из «Мой ритм → Настройки» при сохранении включённых напоминаний.
7. Поддерживайте подпись актуальной через SideStore. Для бесплатной учётной записи срок обычно 7 дней; ориентируйтесь на счётчик приложения в SideStore. Доступно до трёх одновременно установленных приложений, включая сам SideStore, и действуют ограничения App IDs. [Источник: SideStore FAQ](https://docs.sidestore.io/docs/faq).

При обновлении сначала экспортируйте JSON из настроек. Устанавливайте новую IPA поверх существующей с той же учётной записью и идентификатором приложения, не удаляя приложение. Удаление приложения удаляет его локальный дневник.

## Что именно подписывается

Основной IPA содержит `Payload/NezhnyRitm.app` и исполняемый ARM64 Mach-O для iPhoneOS с минимумом iOS 16. Сборка использует `CODE_SIGNING_ALLOWED=NO`, не содержит чужого provisioning profile, специальных entitlements, App Groups или расширений. SideStore должен создать профиль и подпись во время импорта. CI проверяет упаковку, платформу, архитектуру и наличие ресурсов. Это проверка формата и сборки, а не подтверждение фактической установки с конкретной учётной записью Apple.

## Вариант HealthKit

Артефакт **NezhnyRitm-HealthKit** компилирует код HealthKit и содержит entitlement `com.apple.developer.healthkit` и `NSHealthShareUsageDescription`. В IPA используется техническая ad-hoc подпись, чтобы entitlement был доступен инструменту переподписи. Она сама по себе **не позволяет установить приложение**. Окончательная Apple-подпись и provisioning profile должны разрешать HealthKit. Наличие оплаченной команды или файл entitlements сами по себе не гарантируют, что выбранный путь SideStore сохранит capability.

Не рассчитывайте на HealthKit при обычной бесплатной подписи. Если профиль или SideStore не поддерживает эту возможность, используйте основной **NezhnyRitm.ipa**. Для HealthKit надёжный путь — зарегистрировать App ID с HealthKit в подходящей Apple Developer Team, выбрать эту команду в Xcode и подписать конфигурацию `HealthRelease` согласованным профилем. [Документация Apple по HealthKit](https://developer.apple.com/documentation/xcode/configuring-healthkit-access).

Приложение запрашивает только чтение шагов. iOS намеренно не раскрывает, отказал ли пользователь в чтении: отсутствие выборки показывается как «нет доступных данных», без выдуманного нуля. Ручная запись имеет приоритет и никогда не складывается с HealthKit. Синхронизация выполняется при открытии приложения, смене даты, вручную и через observer во время работы приложения. Фоновая доставка не включена.

## Проверка на iPhone XR

- Запуск на iOS 16 или новее; пять вкладок, светлая и тёмная темы.
- Отметьте подход, закройте и откройте приложение: отметка должна сохраниться.
- Добавьте фото еды, переключите день и вернитесь: запись должна остаться.
- Введите шаги, сформируйте отчёт, проверьте копирование и системное «Поделиться».
- Экспортируйте JSON, импортируйте его обратно после подтверждения; проверьте фото и подходы.
- Разрешите уведомления и выберите ближайшее время. Проверьте доставку на заблокированном экране.
- В HealthKit-варианте отдельно проверьте разрешённый и запрещённый доступ. Для базовой сборки этот пункт не нужен.
